Configuration for a _Business Service_ project is done within the `META-INF/application.properties` file in both Quarkus and Spring Boot.

This file will also contain other configuration properties for the application.

This comprehensive reference lists all available properties in a _Business Services_ project, including their descriptions, types, possible values, and defaults.

These properties affect the entire application regardless of what features are being used.

When shared, Quarkus looks for running containers using label-based service discovery.
If a matching container is found, it is used, so a second one is not started.
Otherwise, Dev Services for a new Data-Index instance is started.

== Additional Configuration Notes

=== Property Precedence

Properties can be overridden using different mechanisms:

1. System properties (`-Dproperty=value`)
2. Environment variables
3. `application.properties` file
4. Profile-specific properties (e.g., `%dev.property=value`)

=== Profile-Specific Configuration

Quarkus supports configuration profiles. Prefix properties with `%profile.` to make them profile-specific:

[source,properties]
----
# Production
kogito.persistence.type=jdbc

# Development only
%dev.kie.flyway.enabled=true
%dev.quarkus.swagger-ui.always-include=true

# Test only
%test.kogito.persistence.type=filesystem
----

=== Environment Variable Mapping

Properties can be set via environment variables by:

1. Converting to uppercase
2. Replacing dots (`.`) with underscores (`_`)
3. Replacing dashes (`-`) with underscores (`_`)

Example: `kogito.service.url` becomes `KOGITO_SERVICE_URL`

=== Spring Boot Specific Notes

While most properties work in both Quarkus and Spring Boot, some are framework-specific:

- Properties starting with `quarkus.` are Quarkus-specific
- Spring Boot uses standard Spring configuration mechanisms
- The `kogito.*` and `kie.*` properties work in both frameworks
