= Application properties reference
include::../partials/attributes.adoc[]

This reference lists all `application.properties` configuration properties supported by {PRODUCT_SHORT} (BAMOE), organized by use case.
Properties with a `kogito.*` prefix are part of the Kogito runtime engine.
Properties with a `bamoe.*` prefix are specific to {PRODUCT_SHORT}.
Properties with a `kie.*` prefix are part of the KIE framework.
Quarkus-specific properties (`quarkus.*`) and MicroProfile messaging properties (`mp.messaging.*`) are also included where they relate directly to {PRODUCT_SHORT} configuration.

[NOTE]
====
Unless otherwise noted, all properties are set in the `src/main/resources/application.properties` file of your _Business Service_ project.
====

== Persistence

Configure how {PRODUCT_SHORT} stores process and task state.

[%header,cols="3,3,1,1"]
|===
|Property |Description |Type |Default

|`kogito.persistence.type`
|Sets the persistence backend for the Workflow engine. Use `jdbc` for production relational database persistence.
|String
|`memory`

|`kogito.persistence.optimistic.lock`
|Enables optimistic locking to prevent race conditions when multiple threads access the same process instance concurrently. When enabled, a concurrent access attempt throws an optimistic lock exception that is retried by the fault-tolerance system.
|Boolean
|`false`

|`kogito.transactionEnabled`
|Globally enables or disables transactional operations for the entire application.
|Boolean
|`true`

|`kogito.processes.transactionEnabled`
|Enables or disables transactions for the Process API layer only, overriding the global `kogito.transactionEnabled` value.
|Boolean
|`true`

|`kogito.usertasks.transactionEnabled`
|Enables or disables transactions for the User Tasks API layer only, overriding the global `kogito.transactionEnabled` value.
|Boolean
|`true`

|===

.Example: enabling JDBC persistence with optimistic locking
[source,properties]
----
kogito.persistence.type=jdbc
kogito.persistence.optimistic.lock=true
----

See also: xref:../workflow/database-considerations.adoc[Database considerations].

== Database schema initialization (KIE Flyway)

KIE Flyway can automatically create the required database tables on first run.
Disable it in production environments and apply DDL scripts manually instead.

[%header,cols="3,3,1,1"]
|===
|Property |Description |Type |Default

|`kie.flyway.enabled`
|Enables or disables automatic database schema creation by KIE Flyway. Set to `false` in production and apply the DDL scripts from `bamoe-{VERSION}-db-utils.zip` manually.
|Boolean
|`true`

|===

.Example: disabling KIE Flyway for production
[source,properties]
----
kie.flyway.enabled=false
----

.Example: enabling KIE Flyway only in dev mode (Quarkus profile prefix)
[source,properties]
----
kie.flyway.enabled=false        # for production
%dev.kie.flyway.enabled=true
----

See also: xref:../building-deploying/services-deployment.adoc[Services deployment].

== Jobs Service

Configure the embedded Jobs Service scheduler behavior.

[%header,cols="3,3,1,1"]
|===
|Property |Description |Type |Default

|`kogito.jobs-service.schedulerChunkInMinutes`
|Interval in minutes at which the embedded Jobs Service synchronizes jobs from the persistent store into memory. Used in multi-Pod deployments to ensure that jobs created by a terminated pod are picked up by another pod.
|Integer
|`10`

|`kogito.jobs-service.exception-details-enabled`
|When set to `true`, detailed error information for failed jobs is exposed in the {MANAGEMENT_CONSOLE} Jobs view.
|Boolean
|`false`

|`kogito.jobs-service.numberOfWorkerThreads`
|Sets the number of worker threads used by the Jobs Service. Set to `1` as a workaround when extra tasks are generated after timer node execution in a multi-instance subprocess.
|Integer
|_(not set)_

|`kogito.jobs-service.management.heartbeat.management-id`
|Required when upgrading from {VERSION_92X} Jobs Service to the embedded Jobs Service. Set to a unique string identifier for the job management heartbeat.
|String
|_(not set)_

|===

.Example: Jobs Service configuration
[source,properties]
----
kogito.jobs-service.schedulerChunkInMinutes=10
kogito.jobs-service.exception-details-enabled=true
----

See also: xref:../building-deploying/services-deployment.adoc[Services deployment].

== Event-driven Workflows

Configure Kafka messaging channels for process and user task events.

[%header,cols="3,3,1,1"]
|===
|Property |Description |Type |Default

|`kogito.events.usertasks.enabled`
|Enables or disables publishing of User Task instance events to the configured messaging channel.
|Boolean
|`true`

|`kogito.events.variables.enabled`
|Enables or disables publishing of process variable change events to the configured messaging channel.
|Boolean
|`true`

|`kogito.events.incoming`
|_(Spring Boot)_ Name of the incoming Kafka topic for Kogito process events.
|String
|`kogito-events`

|`kogito.events.outgoing`
|_(Spring Boot)_ Name of the outgoing Kafka topic for Kogito process responses.
|String
|`kogito-responses`

|`kogito.addon.messaging.incoming.defaultName`
|_(Quarkus)_ Default channel name used for incoming messages when no explicit channel mapping is found for a message name.
|String
|`kogito_incoming_stream`

|`kogito.addon.messaging.outgoing.defaultName`
|_(Quarkus)_ Default channel name used for outgoing messages when no explicit channel mapping is found for a message name.
|String
|`kogito_outgoing_stream`

|`kafka.bootstrap.servers`
|Kafka broker URL used by the SmallRye Reactive Messaging connector.
|String
|_(not set)_

|`mp.messaging.outgoing.<channel>.connector`
|Declares the messaging connector for a named outgoing channel. Use `smallrye-kafka` for Kafka.
|String
|_(not set)_

|`mp.messaging.outgoing.<channel>.topic`
|Kafka topic name for a named outgoing channel.
|String
|_(same as channel name)_

|`mp.messaging.outgoing.<channel>.value.serializer`
|Serializer class for Kafka message values on a named outgoing channel.
|String
|_(not set)_

|`mp.messaging.incoming.<channel>.connector`
|Declares the messaging connector for a named incoming channel. Use `smallrye-kafka` for Kafka.
|String
|_(not set)_

|`mp.messaging.incoming.<channel>.topic`
|Kafka topic name for a named incoming channel.
|String
|_(same as channel name)_

|`mp.messaging.incoming.<channel>.value.deserializer`
|Deserializer class for Kafka message values on a named incoming channel.
|String
|_(not set)_

|===

.Example: enabling Kafka event channels for all event types
[source,properties]
----
kafka.bootstrap.servers=localhost:9092

mp.messaging.outgoing.kogito-processinstances-events.connector=smallrye-kafka
mp.messaging.outgoing.kogito-processinstances-events.topic=kogito-processinstances-events
mp.messaging.outgoing.kogito-processinstances-events.value.serializer=org.apache.kafka.common.serialization.StringSerializer

mp.messaging.outgoing.kogito-usertaskinstances-events.connector=smallrye-kafka
mp.messaging.outgoing.kogito-usertaskinstances-events.topic=kogito-usertaskinstances-events
mp.messaging.outgoing.kogito-usertaskinstances-events.value.serializer=org.apache.kafka.common.serialization.StringSerializer

mp.messaging.outgoing.kogito-variables-events.connector=smallrye-kafka
mp.messaging.outgoing.kogito-variables-events.topic=kogito-variables-events
mp.messaging.outgoing.kogito-variables-events.value.serializer=org.apache.kafka.common.serialization.StringSerializer

mp.messaging.outgoing.kogito-processdefinitions-events.connector=smallrye-kafka
mp.messaging.outgoing.kogito-processdefinitions-events.topic=kogito-processdefinitions-events
mp.messaging.outgoing.kogito-processdefinitions-events.value.serializer=org.apache.kafka.common.serialization.StringSerializer
----

.Example: disabling event channels selectively
[source,properties]
----
kogito.events.usertasks.enabled=false
kogito.events.variables.enabled=false
----

See also: xref:../workflow/event-driven-workflow.adoc[Event-driven Workflows].

== Security and authentication

=== Quarkus (OIDC)

[%header,cols="3,3,1,1"]
|===
|Property |Description |Type |Default

|`quarkus.oidc.enabled`
|Enables the Quarkus OpenID Connect (OIDC) extension.
|Boolean
|`true`

|`quarkus.oidc.tenant-enabled`
|Specifies whether the OIDC tenant configuration is active.
|Boolean
|`true`

|`quarkus.oidc.auth-server-url`
|Base URL of the OIDC authorization server (Identity Provider).
|URI
|_(not set)_

|`quarkus.oidc.client-id`
|Client ID of the application registered with the Identity Provider.
|String
|_(not set)_

|`quarkus.oidc.credentials.secret`
|Client secret used with the `client_secret_basic` authentication method.
|String
|_(not set)_

|`quarkus.oidc.roles.role-claim`
|JSON path to the roles claim within the JWT token (for example, `realm_access.roles`).
|String
|_(not set)_

|`quarkus.http.auth.permission."<name>".paths`
|Comma-separated list of HTTP paths covered by the named permission rule. A path ending in `/*` is treated as a prefix match.
|List of URI
|_(not set)_

|`quarkus.http.auth.permission."<name>".policy`
|HTTP authorization policy for the named permission rule. Built-in values: `permit`, `deny`, `authenticated`.
|String
|_(not set)_

|===

.Example: Quarkus OIDC and HTTP authorization
[source,properties]
----
quarkus.oidc.enabled=true
quarkus.oidc.tenant-enabled=true
quarkus.oidc.auth-server-url=http://localhost:8280/auth/realms/kogito
quarkus.oidc.client-id=kogito-service
quarkus.oidc.credentials.secret=secret

quarkus.http.auth.permission.authenticated.paths=/*
quarkus.http.auth.permission.authenticated.policy=authenticated
quarkus.http.auth.permission.public.paths=/q/*,/docs/*,/oidc/info
quarkus.http.auth.permission.public.policy=permit
----

[%header,cols="3,3,1,1"]

|_(not set)_
