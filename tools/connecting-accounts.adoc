= Connecting to Git and Cloud providers

As mentioned previously, {CANVAS} does not feature its own authentication mechanism.
Instead, {CANVAS} allows the linking of existing accounts from Git and Cloud providers.
These accounts are utilized for Git operations such as Pull and Push, and for creating Dev Deployments, respectively.

All connected accounts are visible in the Accounts modal, which is accessible through the person icon in the top-right corner.
This modal displays the number of repositories and deployments being used by those accounts.
Clicking on the arrow provides further information about the accounts, including the date they were linked to {CANVAS}.

Accounts can be removed from {CANVAS} through the Accounts modal.
Removing an account will result in repositories linked to Git provider accounts losing the ability to Push and Pull.
The account linked to a repository can be changed at any time using the dropdown available on the Editor page of any file in the repository.

== Re-authentication support in BAMOE Canvas

BAMOE Canvas now supports seamless renewal of authentication sessions for both cloud and Git providers. The system introduces a **Re-authenticate** button for sessions that become invalid, allowing users to renew credentials without re-entering all configuration details manually.

The re-authentication flow enables users to update expired or invalid authentication sessions efficiently. When a session becomes invalid due to token expiration or revocation, the system detects the invalid state, displays the **Re-authenticate** button next to the affected session, and launches a modal pre-filled with the session’s existing provider and account information. Users are prompted to enter a new valid token, which the system validates before updating the session in place. All session details except the token are pre-filled during this process.

The user interface now integrates the re-authentication option across key areas of BAMOE Canvas where authentication sessions are utilized. In the **My Profile** section, users can view and manage all connected accounts, including re-authenticating any invalid ones. Within the Share Modal, the system prompts users to re-authenticate if the Git provider session is invalid when attempting to share resources. For Dev Deployments, cloud provider sessions now support re-authentication directly from the deployment interface.

The system also includes improvements in session management. It tracks the validity of each authentication session in real-time and automatically marks sessions as invalid when tokens expire or are revoked.
