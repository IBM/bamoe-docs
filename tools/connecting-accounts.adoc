= Connecting to Git and Cloud providers
include::../partials/attributes.adoc[]
include::../styles/images.adoc[]

As mentioned previously, {CANVAS} does not feature its own authentication mechanism.
Instead, {CANVAS} allows the linking of existing accounts from Git and Cloud providers.
These accounts are utilized for Git operations such as Pull and Push, and for creating Dev Deployments, respectively.

All connected accounts are visible in the Accounts dialog, which is accessible through the person icon in the top-right corner.
This dialog displays the number of repositories and deployments being used by those accounts.
Clicking on the arrow provides further information about the accounts, including the date they were linked to {CANVAS}.

Accounts can be removed from {CANVAS} through the Accounts dialog.
Removing an account will result in repositories linked to Git provider accounts losing the ability to Push and Pull.
The account linked to a repository can be changed at any time using the dropdown available on the Editor page of any file in the repository.

== Connecting to GitLab in BAMOE Canvas
GitLab is a comprehensive DevOps platform that supports source code management, continuous integration/continuous deployment (CI/CD), and team collaboration. This section explains how to connect and use GitLab within BAMOE Canvas.

.Procedure
. Navigate to *Profile* → *Connect to an Account* in BAMOE Canvas.
. Select GitLab from the list of providers.
. Enter your *Personal Access Token* to establish the connection.
+
NOTE: You must authenticate using credentials or a personal access token associated with your Git provider. You can manage authentication sessions through the Accounts dialog in Canvas settings.
+
. To create repository from BAMOE workspace:
.. Navigate to *Share* → *Authentication Source*, and select *GitLab* from the dropdown.
.. Click *Create GitLab Repository*.
.. Click *Create* to generate a new repository in your GitLab account. After successful creation, BAMOE displays a success message along with the repository URL.


.Integration features
BAMOE Canvas supports the following GitLab integration features:

* Repository Cloning: You can clone entire repositories hosted on GitLab into the BAMOE workspace.
* Import Files from Repositories or Branches: You can import a specific file from a repository or a specific branch.
* Create Repository from BAMOE Workspace: You can create a new repository from the BAMOE workspace.
* Push and Pull Changes: You can make changes in the workspace and push them to the remote repository, or pull updates from the remote repository.
* Code Snippets: You can create and manage code snippets, including personal snippets and project snippets.


== Connecting to Bitbucket Data Center in BAMOE Canvas

Bitbucket Data Center is a self-managed, enterprise-grade Git repository management solution. This section explains how to connect and use Bitbucket Data Center with BAMOE Canvas.

.Procedure
. Navigate to *Profile* → *Connect to an Account* in BAMOE Canvas.
. Select Bitbucket from the list of providers.
. Provide the *Username* and *Personal Access Token* to establish the connection.
+
NOTE: The access token must be generated from a Bitbucket Data Center user account. 
+
. To create repository from BAMOE workspace:
.. Navigate to *Share* → *Authentication Source*.
.. Select the authentication provider.
.. Choose a project to create the repository (private by default).

NOTE: Only projects where the authenticated user has repository creation permissions will be listed. If no project is available or the user lacks permissions, BAMOE will display a warning.

.Integration features
BAMOE Canvas supports the following Bitbucket Data Center integration features:

* Repository cloning: You can clone entire repositories hosted on Bitbucket Data Center into the BAMOE workspace. 
* Repository cloning in branches: You can clone the repositories on a specific branch.
* Import files from repositories or branches: You can import a specific file from a repository or a specific branch.
* Push and Pull Changes: You can make changes in the workspace and push them to the remoterepository after cloning or creating it. You can also pull updates from the remote repository.
