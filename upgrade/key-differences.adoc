Migrating from BAMOE v8 to v9 involves more than just upgrading libraries, it is a shift in architecture, development model, and runtime behavior. This section highlights the most important differences to help you understand what has changed and how it may impact your applications and what to expect when transitioning to the new BAMOE v9.

== Architecture, Tooling, and Development Workflow

    * From Monolith to Cloud-Native: BAMOE v8 followed a centralized architecture with Business Central and KIE Server. BAMOE v9 adopts a cloud-native approach, built on Kogito, where business logic is packaged as independent services or embedded into applications.

    * Business Central Deprecated: Business Central is no longer part of the toolchain. It is replaced by:
        - BAMOE Developer Tools for VS Code – Targeting developer users.
        - BAMOE Canvas – Targeting business analysts.
        - BAMOE Maven Repository - To build and test Business Services projects.

    * Authoring and Execution Split: In v9, there's a clean separation between asset authoring (offline, in source control) and runtime execution (packaged into applications or services).

    * KIE Server Removed: 
    
    In BAMOE v8, the KIE Server acted as a centralized runtime engine, following a client-server architecture. Applications would interact with it over REST or JMS to execute processes, rules, and decisions.

    In BAMOE v9, this centralized model is replaced by a decentralized, cloud-native approach:

    * You now build and deploy business assets (processes, rules, decisions) as independent microservices (also known as Business Services), using Kogito with Quarkus or Spring Boot. These services expose REST endpoints automatically. Learn more in [Upgrading Client-Server Projects](../06-upgrading-projects/02-upgrading-client-server-projects/).

    * Alternatively, you can embed business logic directly into Java applications. This is not the same as a Kogito-based service. It refers to plain Java applications that use the Drools or jBPM libraries directly, without relying on the Kogito runtime. Learn more in [Upgrading Standalone Projects](../06-upgrading-projects/03-upgrading-standalone-projects/).
      
    * No More Shared KIE Sessions: 
    
    In BAMOE v8, KIE sessions (stateful/stateless) were managed centrally by the KIE Server and exposed via REST or JMS. This allowed shared access to rule and process execution contexts.
    
    In BAMOE v9, KIE sessions still exist, but they are embedded within each application or service. They are no longer shared or exposed through a centralized runtime.

    This architectural change removes the ability to access or manipulate shared rule facts across processes via a central session.


== Runtime Behavior and Persistence

    * Persistence and State Management: In BAMOE v9, persistence is optional like BAMOE v8 and explicitly configured when needed. However, official support is limited to:
        - PostgreSQL 16.8
        - Microsoft SQL Server 2022 This ensures compatibility and support for these platforms, aligning with IBM’s tested environments. Persistence is handled through the Data Index and Data Audit subsystems, which track and expose process and task state.

    * Event-Driven Architecture: BAMOE v9 supports reactive, event-driven applications through integration with Apache Kafka. This enables services to publish and consume events in real time, facilitating decoupled and scalable system design. Quarkus provides the most complete support for BPMN and reactive messaging in this context.

== Production Environment

    * Runtime Execution Model: v8 used KIE Server as the central runtime. In v9, each Business Service project can be packaged and deployed as an independent, containerized service.

    * SmartRouter Deprecation: SmartRouter, which in v8 was used to route client requests to the appropriate KIE containers, is deprecated. Service discovery and orchestration are now handled through Kubernetes solutions.

    * Monitoring and Management: Business Central's runtime dashboards are replaced by:
        BAMOE Management Console
        Integration with observability tools such as Prometheus and GraphQL for querying process and task data.

== Asset Authoring and Compatibility

    * BPMN: A completely new BPMN editor with improved UX.

    * DMN: Rebuilt using React, the new editor supports DMN 1.5 and offers better integration and validation.

    * Guided Assets Deprecated: Guided Rules, Guided Decision Tables, and other guided assets are no longer supported. These must be converted to DRL format. See Guided Assets chapter for more information.

    * Test Scenarios: The new Test Scenario Editor supports DMN 1.5. DRL-based test scenarios have limited support. Currently, mixing DRL and DMN in the same test module is not supported. See Test Scenarios (SCESIM) chapter for more information.

    * Forms: v8 Forms are not compatible in v9. New forms must be created using the BAMOE Developer Tools for VS Code. See Forms chapter for more information.

== Security and Governance

    * Authentication & Authorization: 
       BAMOE v9 integrates with external Identity Providers (IDPs) such as Keycloak, OIDC, and LDAP, using the security capabilities of the chosen runtime (Quarkus or Spring Boot). This enables secure, standardized authentication mechanisms and aligns with modern enterprise infrastructure.

    * User and Role Management:
        User and role definitions are no longer handled via Business Central. Instead, they must be configured externally using your selected IDP or through application-level configuration, depending on the runtime. This allows for centralized identity and access control across services.

        See xref:../upgrade/upgrading-authen-author.adoc[Upgrading Authentication/Authorization] for more details and examples.
        
        
        
== Testing

    * Testing Approach: 
    
    In BAMOE v8, Business Central provided a graphical interface for authoring and executing tests, including support for SCESIM files (scenario-based rule testing).

    In BAMOE v9, testing is fully integrated into the developer workflow using Maven-based unit and integration tests.

    SCESIM files (used for scenario-based rule testing) are still supported and can be executed via Maven. The SCESIM Editor is also still available for authoring and editing Test Scenarios. However, there is no graphical interface for executing tests or viewing results. Test outcomes are available in the console or build output.

    
== Versioning and Collaboration

    * No Embedded Git UI: Source control and collaboration are now managed using external Git platforms (e.g., GitHub, GitLab, Bitbucket), which integrates more naturally with modern CI/CD workflows. The mentioned Git providers are supported by BAMOE Canvas.

== Deployment and CI/CD Integration

    * Deployment Targets: Version9 is designed for Kubernetes, OpenShift, and other container orchestration platforms out of the box.

    * CI/CD Friendly: All components (processes, rules, decisions) are now text-based and version-controlled, making them easy to integrate into CI/CD pipelines.
