= Managing custom tasks in Visual Studio Code

This guide explains how to create, package, and deploy custom Work Item Handlers using Visual Studio Code and Apache Maven, targeting Red Hat Process Automation Manager.

== Prerequisites

Ensure the following tools are installed:

* Java JDK 11 or later
* Apache Maven
* Visual Studio Code with Java and Maven extensions

== Adding Maven Dependencies

Open your project in VS Code and edit the `pom.xml` file to include any required dependencies for your Work Item Handler. For example:

[source,xml]
----
<dependencies>
  <dependency>
    <groupId>org.kie</groupId>
    <artifactId>kie-api</artifactId>
    <version>7.73.0.Final</version>
  </dependency>
  <!-- Add other dependencies as needed -->
</dependencies>
----

== Packaging the Project

In the terminal, navigate to the root folder of your project (where `pom.xml` is located) and run:

[source,bash]
----
mvn clean package
----

This command compiles the project and creates output files in the `target/` directory.

== Output Files

After packaging, the following files will be generated in the `target/` directory:

[cols="1,2", options="header"]
|===
| File Name | Description

| `myworkitems-<version>.jar`
| Used for direct deployment to Red Hat Process Automation Manager.

| `myworkitems-<version>.zip`
| Used for deployment via a service repository.
|===

Replace `<version>` with the version specified in your `pom.xml`.

== Implementing the Work Item Handler

Here are key code snippets and their purposes when implementing a custom Work Item Handler:

[cols="1,2", options="header"]
|===
| Parameter / Code Snippet | Description

| `RequiredParameterValidator.validate(this.getClass(), workItem);`
| Ensures all required parameters are present. Throws `IllegalArgumentException` if any are missing.

| `String sampleParam = (String) workItem.getParameter("SampleParam");`
| Retrieves a parameter from the `WorkItem`. The parameter name is always a string. Casting may be required.

| `// complete workitem impl…`
| Placeholder for your custom Java logic that executes when the handler is triggered.

| `results.put("SampleResult", sampleResult);`
| Adds output data to the result map. These values are passed back to the process.

| `manager.completeWorkItem(workItem.getId(), results);`
| Marks the work item as complete and sends the results to the process engine.

| `abortWorkItem()`
| Optional method to abort the work item. Can be left empty if not needed.
|===
