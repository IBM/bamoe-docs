= Using correlation to manage messaging with multiple process instances


You can use the correlation feature, when multiple process instances are running concurrently and only one specific instance needs to be notified. Correlations let you bind process instances to messages containing specific property values. The correlation feature is based on the `EventTypeFilter` which adds a new level of filtering based on the content of the message.

You can configure correlation in the following ways: 

* Static: using a `MessageStartEvent`, or 

* Dynamic: using a `MessageIntermediateCatchEvent` or a `MessageBoundaryEvent`.


Correlation property settings are only available in the BPMN plug-in for VS Code. This process does not apply to {central} web designer.

For information about correlation key assigned to the process instance, see xref:{enterprise-dir}/admin-and-config/correlationkey-entities-ref.adoc[Correlation key entities].


== Prerequisites

* Configure the KIE Server to send and receive Kafka messages from the process. For more information, see xref:kieserver-kafka-proc_{context}[]. 

== Using Static correlation in MessageStartEvent

To use static correlation in `MessageStartEvent` follow these steps:

. Navigate to *Implementation/Execution* -> *Message property* field and define the Kafka channel name.

. Navigate to *Process properties* -> *Collaboration* -> *Correlations* and define a correlation for the process by entering the value for ID, Name, Property ID, Property Name, and Property Type fields.
+

.Correlations window
image::BPMN2/correlation-window.png[Correlation window]
+

. Create a process with a `MessageStartEvent` and enter the values for the following correlation fields:

* Property: Select the correlation that you have already created.

* Message Expression: Define the variable name that will be available in the generated event.

* Message Expression Type: Select the appropriate expression type (for example, String, Long, Object).

* Data Expression: Define the expected values to trigger the process from the generated event.

* Data Expression Type: Select the appropriate expression type (for example, String, Long, Object).

As shown in the following example:

.Correlation fields
image::BPMN2/correlation-fields.png[Correlation fields]


After configuring the correlation, the system uses the defined correlation key (for example, `CorrelationKeyName`) to evaluate incoming messages. For each message, the system computes a correlation key instance based on the message content. For example, the system extracts the payment value and populates the status property of the correlation key, with the following response:

[source,shell]
----
 CorrelationKeyName {status = OK}.
----

If the computed key matches an existing subscription, the system initiates a new process instance using the message. If no match is found, the message is rejected and the process does not start.

To start the process, you can send a message to the configured correlation using any messaging tool. You can execute the Kafka command-line utility inside a running Docker container to send the message, for example:

[source,shell]
----
docker exec -it loan-kafka /opt/kafka/bin/kafka-console-producer.sh \
--broker-list localhost:9092 \
--topic correlation
----

Sample response message:

[source,shell]
----
{"data": { "status" : "OK" }}
----


== Using Dynamic correlation in MessageIntermediateCatchEvent or MessageBoundaryEvent

Defining the dynamic correlation key is similar to static correlations. To use dynamic correlation in `MessageIntermediateCatchEvent` or `MessageBoundaryEvent` follow these steps:

. Create a BPMN process with `MessageIntermediateCatchEvent` or `MessageBoundaryEvent` and create a process variable (for example, `ProcessVarOrderId` of type String) that can be used to trigger the nodes.
. Navigate to *Implementation/Execution* -> *Message property* and define the Kafka channel name for `MessageIntermediateCatchEvent` or `MessageBoundaryEvent`.
. Navigate to *Process properties*-> *Collaboration*-> *Correlations* and define a Correlation for the process by entering the value for ID, Name, Property ID, Property Name, and Property Type fields.
+
.Correlations window
image::BPMN2/correlation-window.png[Correlation window]
+

. Create a BPMN process for `MessageIntermediateCatchEvent` or `MessageBoundaryEvent`, and enter the values for the following correlation fields:
+
* Property: Select the correlation that you have already created.

* Message Expression: Define the variable name that will be available in the generated event.

* Message Expression Type: Select the appropriate expression type (for example, String, Long, Object).

* Data Expression: Define the expected values to trigger the process from the generated event.

* Data Expression Type: Select the appropriate expression type (for example, String, Long, Object).

.Correlation fields
image::BPMN2/correlation-fields-dynamic.png[Correlation fields]


The jbpm engine will compute the correlation subscription based on the dynamic expression which uses the process variables (for example, `ProcessVarOderId`).

In dynamic correlation, the jBPM engine registers the correlation subscription using an expression that evaluates process variables at runtime. For example, if the process variable `ProcessVarOrderId` holds the value 1 at the time of evaluation, the engine sets the correlation key as `CorrelationKey {ProcessVarOrderId = 1}`.

When a process instance is started with `{ProcessVarOrderId = 1}`, it enters a waiting state at either an `MessageIntermediateCatchEvent` or a `MessageBoundaryEvent`. The process resumes execution only when a message is received that matches the correlation key, for example:

[source,shell]
----
{"data": { "ProcessVarOrderId" : "1" }}
----

The engine resumes the execution of the process only if the value in the incoming message matches the value of the process variable used in the correlation key. If there is no match, the message is ignored and the process remains in the waiting state.
