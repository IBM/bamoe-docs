= Clustering using multiple headless controller and multiple KIE Servers

You can configure {PRODUCT} to run in a clustered environment by using multiple headless controllers and multiple
KIE Server. The headless controller provides centralized management and
configuration, while multiple KIE Servers execute business processes in a clustered
and highly available manner.

*Configuring headless controller nodes*

To configure the headless controller nodes, add the following
properties under the `<system-properties>` element in the `EAP_HOME/standalone/configuration/standalone-full.xml` file

[source,xml]
----
<system-properties>
   <property name="org.kie.server.user" value="<USERNAME>"/>
   <property name="org.kie.server.pwd" value="<USER_PWD>"/>
   <property name="org.kie.server.controller.templatefile.watcher.enabled" value="true"/>
   <property name="org.kie.server.controller.templatefile" value="/NFS_STORAGE/path/template-storage.xml"/>
  . ..
</system-properties>
----

Replace `<USERNAME>` and `<USER_PWD>` with the actual credentials. You must have the `kie-server` role defined.

The template file stored on the shared NFS location contains default configuration
information used by the controllers to manage KIE Server deployments.

If the `org.kie.server.controller.templatefile.watcher.enabled` property is set to true,, the controller periodically checks the template
file for changes. The default polling interval is 30000 milliseconds and can be modified
by using the `org.kie.server.controller.templatefile.watcher.interval` system property.
If the value of this property is set to false, changes take effect only after the controller restarts.

*Configuring KIE Server nodes*

To configure the KIE Server nodes, deploy `kie-server.war` on the node and update the
`EAP_HOME/standalone/configuration/standalone-full.xml` file by adding the following
properties under the `<system-properties>` element:

[source,xml]
----
<property name="org.kie.server.controller.user" value="<CONTROLLER_USER>"/>
<property name="org.kie.server.controller.pwd" value="<CONTROLLER_PWD>"/>
<property name="org.kie.server.id" value="<KIE_SERVER_ID>"/>
<property name="org.kie.server.location" value="http://<HOST>:<PORT>/kie-server/services/rest/server"/>
<property name="org.kie.server.controller" value="http://20.20.20.20:8080/controller/rest/controller,http://10.10.10.10:8080/controller/rest/controller"/>
----

* `org.kie.server.controller.user` and `org.kie.server.controller.pwd`: Specify the
  credentials used to authenticate with the controllers.
* `org.kie.server.id`: Uniquely identifies the KIE Server instance.
* `org.kie.server.location`: Specifies the REST endpoint of the KIE Server.
* `org.kie.server.controller`: Defines a comma-separated list of controller URLs.


== High availability with multiple headless controllers

To enable high availability by using a headless controller, configure each KIE Server with more than one controller. 
Specify the controller endpoints by providing a comma-separated list of controller URLs in the org.kie.server.controller system property. For example:

[source,xml]
----
<property name="org.kie.server.controller" value="http://10.10.10.10:8080/controller/rest/controller,http://20.20.20.20:8080/controller/rest/controller"/>
----

When multiple controllers are defined, the KIE Server automatically connects to an
available controller. If the primary controller becomes unavailable,
the KIE Server connects to another configured controller without manual intervention.

Ensure that connectivity to the shared NFS location remains uninterrupted. If the NFS
location is unavailable, the controllers cannot access template and container
configuration data, which can affect cluster operation.

== Clustering KIE Server nodes

KIE Server clustering requires all KIE Server nodes to share the same database.
This shared database stores process instances, runtime state, and KIE sessions.
To setup a kie-server node clusters, add the following system properties to the KIE Server configuration:

[source,xml]
----
<property name="org.kie.server.persistence.ds" value="java:jboss/MySqlXADS"/>
<property name="org.kie.server.persistence.dialect" value="org.hibernate.dialect.MySQL8Dialect"/>
----

* `org.kie.server.persistence.ds`: Specifies the JNDI name of the data source (java:jboss/MySqlXADS).
* `org.kie.server.persistence.dialect`: Specifies the Hibernate dialect to use for the database (MySQL8Dialect for MySQL  compatibility).

These properties configure the database connection for KIE Server.

== Configuring users in the Elytron realm

{PRODUCT_SHORT} uses the Elytron subsystem for authentication and authorization.

Use the following JBoss CLI commands to create users in  Elytron realm in the JBoss EAP server:

[source,bash]
----
/subsystem=elytron/filesystem-realm=ApplicationRealm:add-identity(identity=<USERNAME>)
/subsystem=elytron/filesystem-realm=ApplicationRealm:set-password(identity=<USERNAME>,clear={password=”<PASSWORD>”})
/subsystem=elytron/filesystem-realm=ApplicationRealm:add-identity-attribute(identity=<USERNAME>, name=role, value=[kie-server])
----

Replace `<USERNAME>` and `<PASSWORD>` with the actual username and password.

*Testing High Availability (HA) Setup*

To verify that your HA setup is working correctly:

.Shutdown the primary controller at http://10.10.10.10:8080/controller/.

.Restart the KIE server node.

.After the restart, verify that the KIE Server retrieves container configuration from the secondary controller at http://20.20.20.20:8080/controller/.
