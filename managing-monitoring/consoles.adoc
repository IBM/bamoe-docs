= Managing live Workflows using BAMOE Management Console
include::../partials/attributes.adoc[]
include::../styles/images.adoc[]

{MANAGEMENT_CONSOLE} is a web application used for viewing the state of all available _Business Services_ and managing and interacting with Process Instances:

You can use {MANAGEMENT_CONSOLE} to manage and interact with Process Instances, complete User Tasks, and manage scheduled Jobs. For installation information see xref:../installation/management-console.adoc[Installing Runtime Environment → {MANAGEMENT_CONSOLE}]

You can change the {MANAGEMENT_CONSOLE} interface language either by updating your browser’s language settings or by using the language dropdown on the home screen. By default, the console uses your browser settings, but you can select a specific language to override the browser setting. Once configured, all UI elements in the {MANAGEMENT_CONSOLE} will display in the selected language, ensuring a fully localized experience.

In order to be compatible with {MANAGEMENT_CONSOLE} your _Business Services_ must include the following {PRODUCT_SHORT} subsystems:

* *Data-Index Add-on*: Enables the {MANAGEMENT_CONSOLE} to access stored events related to processes and domain data from your _Business Services_. The Data-Index service requires PostgreSQL persistence.
* *Process Management Add-on*: Enables the {MANAGEMENT_CONSOLE} to interact with the Process data from your _Business Services_ through the add-on REST endpoint `/management/processes`.
If you do not enable this add-on for your _Business Service_, the {MANAGEMENT_CONSOLE} provides read-only access to your service data without the ability to modify instances, such as aborting Process Instances.

To visualize the Process Instance execution path at the {MANAGEMENT_CONSOLE}, add the following add-on:

* *Process SVG add-on*: Enables the Process SVG diagram to visualize the Process Instance execution path.
If this add-on is not enabled for your _Business Service_, the {MANAGEMENT_CONSOLE} does not display the diagram panel.

---

{MANAGEMENT_CONSOLE} consists of the following pages that allow you to interact with your Process Instances and data:

* *Process Definitions*: List process definitions available and automatically generate forms for creating the respective Process Instances.

* *Process Instances*: List process and subprocess instances and filter them by process definition ID/name, Process Instance ID, business key, or status.

* *Jobs*: List available jobs, filter them by Process Instance ID, task ID, process definition ID/name, status, and perform actions for any individual one, such as view details, reschedule, or cancel.

* *Tasks*: List User Tasks from active Process Instances, filter them by Process Instance ID, task ID, process definition ID/name, status, or name, and submit forms to fulfill tasks.

But before you can use these pages, you need to connect your _Business Service_ to the {MANAGEMENT_CONSOLE}.

== Connecting to a _Business Service_

You will be connected to a  _Business Service_ by clicking the **+ Connect to a Business Service...** button and filling in the required information on the modal:

- **Alias**: The name to give your connected _Business Service_ instance (can be anything that helps you identify it).
- **URL**: The _Business Service_ root URL (E.g., http://localhost:8080).
- **Force login prompt (for secured runtimes only)**: Check this if you are already logged in to your Identity Provider but would like to log in again (maybe with a different user).

More settings are available in the **Advanced OpenID Connect settings** section:

- **Client ID**: Overrides the Client ID used for this connection. Defaults to the value of the `RUNTIME_TOOLS_MANAGEMENT_CONSOLE_OIDC_CLIENT_CLIENT_ID` environment variable.
- **Scope**: Overrides the scopes requested from the Identity Provider. Useful from some Identity Providers that, for example, will only grant a Refresh Token if the `offline_access` scope is included in the token request. Defaults to the value of the `RUNTIME_TOOLS_MANAGEMENT_CONSOLE_OIDC_CLIENT_DEFAULT_SCOPES` environment variable.
- **Audience**: This is the `audience` parameter in the Authorization request. Used to identify the service that the token is intended for. Defaults to the value of the `RUNTIME_TOOLS_MANAGEMENT_CONSOLE_OIDC_CLIENT_DEFAULT_AUDIENCE` environment variable.

If your _Business Service_ uses OpenID Connect authentication, you should be redirected to the Identity Provider (IdP) login page or, if you're already logged in, redirected back to the {MANAGEMENT_CONSOLE}. If your _Business Service_ is unsecured, it should connect directly.

Once logged in, the management pages will be displayed in the side menu, listing Process Instances, Process Definitions, Jobs, and Tasks.

image::runtime-services-modeling/mgmt-console-home-add-connection-modal-secured.gif[Image of {MANAGEMENT_CONSOLE} new connection modal]

[NOTE]
For information on how to secure your _Business Service_ and expose the Identity Provider URL to the {MANAGEMENT_CONSOLE}, check xref:../building-deploying/security.adoc[Securing Business Service API endpoints]

=== Pre-configured connected Business Services

It is possible to set up a pre-configured list of Business Services, defined via the `RUNTIME_TOOLS_MANAGEMENT_CONSOLE_MANAGED_BUSINESS_SERVICES` environment variable. This allows users to connect to a pre-defined list of Business Services without having to configure each one manually. To learn how to set them up, check the xref:../installation/management-console.adoc##pre-configured-business-services[installation guide].

On the first load, the Management Console creates authentication sessions for each Business Service listed in the environment variable.

If a Business Service requires authentication, the Management Console display an "Authenticate" button, which will redirect to the login page for the Identity Provider configured in the Business Service, unless the user is already authenticated with the same Identity Provider (using the same `clientId`, `scopes`, and `audience`), in this case the same token is used for all matching Business Services.

--
This panel enables you to explore the Process diagram and execution path of the related Process Instance.
The execution path is displayed when the {MANAGEMENT_CONSOLE} finds the `.svg` resources using the {PRODUCT_SHORT} Process SVG add-on configuration included in the {MANAGEMENT_CONSOLE}.

This panel includes various controls to view the Process diagram, such as *Selection*, *Pan*, *Zoom in*, *Zoom out*, and *Fit to viewer*.
--

=== Details panel
--
This panel displays the basic Process Instance information and provides links to the related Process runtime UI.
If the Process Instance is related to other Process Instances, then links to the parent and subprocess instances are also available in the *Details* panel.

The Details panel consists of the following fields:

* *Name*: The Process Definition ID related to the Process Instance.
* *Business key*: Optional business key of the Process Instance.
* *State*: The state of the Process Instance. The state of a Process Instance can be pending, active, completed, aborted, suspended, or error.
* *Id*: The unique identifier of the Process Instance.
* *Endpoint*: The endpoint of the Process Instance. You can click the displayed endpoint to view the Process or application UI that triggered the Process Instance.
* *Started*: Time reference indicating when the Process Instance is started.
* *Last Updated*: Time reference indicating when the Process Instance is updated.
* *End*: Time reference indicating when the Process Instance is completed.
* *SLA due date*: Time reference for the SLA defined in the Process Instance, if available.
* *Parent Process*: Parent Process Instance of the instance (if linked). You can click and navigate to the parent Process Instance.
* *Sub Processes*: Subprocess of the instance (if linked). You can click and navigate to the subprocess Instances.
--

=== Timeline panel
--
The *Timeline* panel displays the list of node instances related to the Process Instance sorted by the start time.
Each node consists of an icon indicating the state of the node, such as active, completed, or error.

The actions that are available for an active node include retriggering and canceling the node.
Whereas the actions for an error node include retrying and skipping the node.
The node actions in the *Timeline* panel are connected with the _Business Service_ to perform the requested action.

If a node in the *Timeline* panel is associated with a job, then select the clock icon to view the job details or click the menu for additional job operations, such as *Job Reschedule* or *Job Cancel*. The same functionality is available for nodes with associated SLA timers.
--

=== Node Trigger panel
--
The *Node Trigger* panel displays the list of all Process Definition nodes in a drop-down.
When you select a node, the related information is displayed, such as *Node name*, *Node type*, and *Node id*.
Click the *Trigger* button to trigger the selected node.
--

=== Jobs panel
--
The *Jobs* panel displays the list of available jobs that are related to the Process Instance.

You can reschedule or cancel a job that is in a scheduled or error state.
You can also modify the expiration time for one-time jobs and repeat interval, repeat time, and expiration time for the periodic jobs.
--

[#impersonation]
=== Impersonation

User Tasks can be assigned to a specific user or user group, and submitting them is limited to the assigned user. But when using an unsecured _Business Service_ or authenticated as a user with impersonation powers, you can submit the task as the assigned user by impersonating them.

image::runtime-services-modeling/mgmt-console-task-impersonation.png[Image of the Impersonation form]

Fill the **User** and/or **Group** fields in the Impersonation form and click ** Apply** to start impersonating a specific user or user group.

To stop impersonating, click the **Reset** button.

[NOTE]
When viewing User Tasks from a secured _Business Service_ with a user without impersonation powers, only tasks assigned to the current user or user group can be submitted.

=== Managing all connected Business Services at the same time

On the home page, clicking on the *All Business Services* option will make it so that every page that lists resources (such as Process Instances, definitions, tasks, overview, etc) will fetch data from all connected Business Services at the same time.

image::runtime-services-modeling/mgmt-console-home-all-business-services.png[Image of the Home page with the All Business Services button, 400]

This means that from a single Management Console instance, it's possible to manage multiple Business Services and obtain an aggregated view of all running Process Instances, as the Overview page groups Process Instances from matching process definitions, even if they are from different Business Services.

[#process-instance-migration-ui]
== Process Instance Migration
You can use the Process Instance Migration (PIM) functionality to  migrate Process Instances from a source Process Definition to a target Process Definition. To simplify the migration process, {PRODUCT_SHORT} includes a dedicated user interface, integrated in the {MANAGEMENT_CONSOLE}.

The migration of Process Instances should be tested on a duplicate of your production system. Before doing the actual migration, backup your database and plan downtime for your users to avoid conflicting changes on the same processes. Performing a Process Instance Migration on a live system could result in errors, and even data corruption. Only restore access once the migration has finished executing. For more information on managing migration see xref:migration-with-pim.adoc[Migrating your in-flight Process Instances using PIM]

To use this feature, you must:

* Include the xref:../reference-guide/maven-repository-libraries.adoc#PIM-addon-dependency[{PIM_ADDON_SHORT}] dependency in the `pom.xml` of your _Business Service_. If you try to open the PIM UI, you will see an error message stating that "{PIM_ADDON_SHORT} is missing".

* Select a specific _Business Service_ to be migrated as the PIM UI does not support the visualization of multiple _Business Services_.

Once these requirements are satisfied, you can access the PIM UI under `Advanced` in the {MANAGEMENT_CONSOLE}.

image::runtime-services-modeling/mgmt-console-pim-nav.png[Image of the PIM nav item, 300]

=== PIM Plan List

Clicking `Process Instance Migration (PIM)` opens the `PIM Plans` page. Initially, this page is empty until you create a PIM Plan which is required to perform a Process Instance Migration. For more details on the PIM workflow, refer to the xref:migration-with-pim.adoc[{PIM_ADDON_SHORT}].
The image below shows a table with two previously created PIM Plans.

image::runtime-services-modeling/mgmt-console-pim-plan-list.png[Image of the PIM plan list page, 600]

The highlighted fields are:

. Filter PIM Plans by the source or target Process ID.
. Create a new PIM Plan. Clicking this will redirect you to the Create Plan page.
. Delete selected PIM Plan. This button is enabled only if at least one PIM Plan is selected. If the PIM Plan is being used in a migration, it cannot be deleted.
. Select the PIM plan.
. Expand the PIM plan. Expansion is only possible if the PIM Plan contains a node mapping.
. Execute the respective PIM plan. Clicking this will redirect you to the Execute PIM Plan page
. Open additional operations.

=== PIM Plan Creation

A PIM Plan defines the mapping between the source and target process definitions, which is required to perform a migration.

image::runtime-services-modeling/mgmt-console-pim-plan-create-empty.png[Image of the PIM create plan page, 600]

The highlighted fields are:

. Process Mapping: Select the source and target Process Definitions that will be used in the PIM Plan
. Node Mapping: Select nodes from the source and target Process Definitions that should be mapped.
Nodes that can put the Process Instance in a "waiting state" must be mapped or an validation error will be raised. For more details, refer to the xref:migration-with-pim.adoc[Migrating Process Instances using {PIM_ADDON_SHORT}].
. Source Process Definition SVG: Provides a visual representation of the source and Process Definitions.
. Target Process Definition SVG: Provides a visual representation of the target Process Definitions.
. Create PIM Plan button: Clicking on this opens a Summary dialog.

When you select the source and target Process Definitions, the corresponding node lists and SVG diagrams will be updated (if available in the _Business Services_). Selecting a node highlights it in the SVG diagram.

NOTE: Highlighting does not work with SVGs generated using the BPMN Editor (Classic).

image::runtime-services-modeling/mgmt-console-pim-plan-create-filled.gif[PIM Create Plan being filled, 600]

After configuring the PIM Plan, click *Create PIM Plan*. A dialog will display a summary of the PIM Plan.

image::runtime-services-modeling/mgmt-console-pim-plan-create-summary.png[Image of the PIM create plan summary, 600]

Click *Confirm* to proceed with the plan creation.

image::runtime-services-modeling/mgmt-console-pim-plan-create-success.png[Image of the PIM creation plan success with warning, 600]

The PIM Plan will be validated, and any errors or warnings [1] will be listed in the dialog. If validation succeeds, the PIM Plan is created and the *Go to PIM Plan* [2] button becomes available. Clicking *Go to PIM Plan* takes you to the execution page for the PIM Plan you have just created. Clicking *Create another PIM Plan* will leave you on the Create PIM Plan page.

The images below show the PIM Plan execution page.

.. The PIM Plan's process mapping.
.. The PIM Plan's node mapping.

. The Execute PIM Plan button.
. Filter Process Instances: Available only if **Select Process Instances** is chosen. Changing the filter does not immediately update the Process Instances table.
.. Filter by Process Instance ID.

.. Filter by Last Updated Date.
.. Filter by SLA Due Date.
.. Apply the filter to update the Process Instances table.
.. Reset the filter.
.. Select all Process Instances that match the filter.

To execute the PIM Plan we have two high-level filters:

* **All Process Instances**: No limit; migrates all instances matching the PIM Plan.
* **Select Process Instances**: Limited; it can migrate up to 1,000 Process Instances per migration and a maximum of 50 migrations, totaling 50,000 Process Instances.

Clicking *Execute PIM Plan* opens the execution summary.

image::runtime-services-modeling/mgmt-console-pim-plan-execute-summary.png[Image of the PIM execution summary, 600]

The summary includes:

. The process and node mappings from the PIM Plan.
. The chosen configuration.
. The current number of Process Instances matching the PIM Plan.
. Critical warning reminding you to backup your system and avoid exposing it to consumers when executing a PIM Plan, to avoid errors and data corruption, see xref:migration-with-pim.adoc[{PIM_ADDON_SHORT}].
. The *Execute PIM Plan* execution button.

Clicking *Execute PIM Plan* starts the migration. Duration depends on the number of instances. After completion, a message displays the total number of successfully migrated instances.
