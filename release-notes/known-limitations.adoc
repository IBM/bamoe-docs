Table 1. Known limitations

[%autowidth]

|Limitation |Description |Workaround

|Native compilation support for workflow projects.
|Workflow (BPMN) projects do not support native compilation in {PRODUCT_SHORT} {VERSION_93X} and earlier 9.x versions. Using certain dependencies (for example, data-index, jobs-service) might cause native builds to fail due to missing reflection metadata.
|Do not use native compilation if your _Business Services_ include stateful workflow.

|OpenAPI spec auto-generation when using the _io.quarkus:quarkus-oidc_ extension.
|The _io.quarkus:quarkus-smallrye-openapi_ extension will cause errors when starting a Business Service if the _io.quarkus:quarkus-oidc_ extension is also present and no other schema is generated. This only happens if the _io.quarkus:quarkus-oidc_ extension is enabled.
|Add the following to your *application.properties* file:
`quarkus.smallrye-openapi.auto-add-bad-request-response=false`

* This property ensures that "400 Bad Request" outputs are not added to the auto-generated OpenAPI specifications.

|DMN Editor: does not support DMN 1.6 Simplified `InputData` Assignment Across Nested Imports
|Users who rely heavily on imported DMN models to build modular DMN models with layered imports, may encounter issues when their model depends on transitively imported Input Data nodes. This refers to Input Data defined in a model that is imported indirectly through another model. As a result, models using transitive Input Data cannot be:

* Evaluated using DMN Runner

* Tested using Scenario and Simulation files

|To avoid this issue, users must restructure their models to avoid relying on nested imports for Input Data.

|DMN Editor: Copy and paste of data type property creates non-unique copy
|When users attempt to speed up the creation of custom structures by copying and pasting structure properties, will encounter a limitation where the pasted property is not treated as a unique instance.

Although it is valid to have multiple structures with properties of the same name (for example, `Car.Price` and `House.Price`), the editor links the copied property to its original. As a result, any modification made to the pasted property (for example, `House.Price`) will also affect the original (`Car.Price`), and vice versa.

|To avoid this issue, users should manually create the new structure property instead of copying it. 

|DMN Editor: Does not autocomplete decision name when required decision uses namespace in `href`
|In DMN models, when a required decision is referenced by using a full namespace in the `href` attribute (e.g., <requiredDecision href="http://www.example.org/Definitions01.xml#prebureauriskDec01"/>), the expression editor fails to offer autocompletion for that decision. (eg. `prebureauriskDec01` is not in theautocompletion suggestions). This issue only affects references within the same DMN model. 

|To ensure autocompletion works as expected, do not use namespaces in `href` attributes when referencing decisions within the same DMN model. Use relative references (for example, `href="#decisionName"`) instead.

| BAMOE Management Console environment variables not working

| When starting the BAMOE Management Console, error messages related to environment variable validation may appear in the logs. These errors do not prevent the BAMOE Management Console from starting, but any environment variables set will not take effect.

a| Overwrite the initial `env.json` file inside the BAMOE Management Console container by mounting a volume on top of its path with a fixed `env.json` file.

Example (Docker Compose):
[source,shell,subs="attributes+"]
----
services:
  management-console:
    container_name: bamoe-management-console
    image: quay.io/bamoe/management-console:{IMAGE_VERSION}
    platform: linux/amd64
    ports:
      - "8380:8080"
    volumes:
      - /path/to/local/env.json:/management-console/app/env.json
    environment:
      RUNTIME_TOOLS_MANAGEMENT_CONSOLE_OIDC_CLIENT_CLIENT_ID: kie-management-console
----

Fixed initial `env.json` file:
[source,json]
----
{
  "RUNTIME_TOOLS_MANAGEMENT_CONSOLE_APP_NAME": "BAMOE Management Console",
  "RUNTIME_TOOLS_MANAGEMENT_CONSOLE_OIDC_CLIENT_CLIENT_ID": "bamoe-management-console",
  "RUNTIME_TOOLS_MANAGEMENT_CONSOLE_OIDC_CLIENT_DEFAULT_SCOPES": "openid email profile",
  "RUNTIME_TOOLS_MANAGEMENT_CONSOLE_OIDC_CLIENT_DEFAULT_AUDIENCE": "",
  "RUNTIME_TOOLS_MANAGEMENT_CONSOLE_MANAGED_BUSINESS_SERVICES": [],
  "RUNTIME_TOOLS_MANAGEMENT_CONSOLE_BASE_PATH": ""
}
----

| BAMOE Management Console Helm Chart variables not working

| The Helm Chart for BAMOE Management Console includes two variables that are not functional: `pimMaxBulkIterationsCount` and `pimMaxBulkSize`. These variables should be avoided for now. The Management Console container will start, but other environment variables set via Helm Chart values will be ignored.

a| Overwrite the initial `env.json` file inside the BAMOE Management Console container by creating a ConfigMap with a fixed `env.json` and patching the deployment, mounting a volume on top of the initial file.

Create ConfigMap:
[source,shell]
----
kubectl create configmap bamoe-management-console-env \
  --from-literal=env.json='{
  "RUNTIME_TOOLS_MANAGEMENT_CONSOLE_APP_NAME": "BAMOE Management Console",
  "RUNTIME_TOOLS_MANAGEMENT_CONSOLE_OIDC_CLIENT_CLIENT_ID": "bamoe-management-console",
  "RUNTIME_TOOLS_MANAGEMENT_CONSOLE_OIDC_CLIENT_DEFAULT_SCOPES": "openid email profile",
  "RUNTIME_TOOLS_MANAGEMENT_CONSOLE_OIDC_CLIENT_DEFAULT_AUDIENCE": "",
  "RUNTIME_TOOLS_MANAGEMENT_CONSOLE_MANAGED_BUSINESS_SERVICES": [],
  "RUNTIME_TOOLS_MANAGEMENT_CONSOLE_BASE_PATH": ""
}'
----

Patch Deployment:
[source,shell]
----
kubectl patch deployment bamoe-management-console-management-console \
  --type='strategic' \
  -p='
spec:
  template:
    spec:
      volumes:
        - name: env-json-volume
          configMap:
            name: bamoe-management-console-env
      containers:
        - name: management-console
          volumeMounts:
            - name: env-json-volume
              mountPath: /management-console/app/env.json
              subPath: env.json
'
----


| BAMOE Canvas: Misleading Dev Deployment status for Kind/Minikube deployments

| After creating a Dev Deployment targeting Kind or Minikube clusters, BAMOE Canvas fails to retrieve healthcheck data from the deployment and displays it in an error state, even if the deployment succeeded. Dev Deployments targeting OpenShift clusters work as expected.

| It is still possible to access the deployment by manually typing the URL in the browser: `http://localhost/<dev_deployment_id>/q/swagger-ui` for Quarkus and `http://localhost/<dev_deployment_id>/swagger-ui/index.html` for Spring Boot. The error state can be ignored.

|{MCP_SERVER}
|When using the {MCP_SERVER} with the security layer disabled, executing any MCP Tool results in the following exception: `Access token is either invalid or not provided`.
|To avoid this issue, add the following parameter when running the {MCP_SERVER} image:  `-e QUARKUS_OIDC_ENABLED=false`
