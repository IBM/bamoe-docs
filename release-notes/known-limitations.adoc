= Known limitations
include::../partials/attributes.adoc[]
include::../styles/images.adoc[]

Before you use {PRODUCT_LONG}, see the known limitations. When possible, workarounds will be included with the limitations.

Table 1. Known limitations
[%header,cols=3]
[%autowidth]
|===
|Limitation |Description |Workaround

|The event subsystem in the {PRODUCT_SHORT} workflow engine does not have transactional support.
|Using transactions that emit events through an emitter like Kafka or CloudEvents in _Business Services_ with Compact Architecture with at least runtime persistence may throw a transaction error with message 'enlisted connection used without active transaction' after starting a process instance.
|

|In a _Business Service_, Workflows subsystem event related messages are sent even if the process execution fails due to a DB error.
|In a process containing a node that sends out a message (for example, Intermediate Message Throw Event), the sending of the message happens when this node is executed. If the execution then encounters an error (for example, coming from the database) and the transaction is rolled back, the message has already been sent.
|Further investigate event related messages

|Native compilation support for workflow projects.
|Workflow (BPMN) projects do not support native compilation in {PRODUCT_SHORT} {VERSION_93X} and earlier 9.x versions. Using certain dependencies (for example, data-index, jobs-service) might cause native builds to fail due to missing reflection metadata.
|Do not use native compilation if your _Business Services_ include stateful workflow.

|OpenAPI spec auto-generation when using the _io.quarkus:quarkus-oidc_ extension.
|The _io.quarkus:quarkus-smallrye-openapi_ extension will cause errors when starting a Business Service if the _io.quarkus:quarkus-oidc_ extension is also present and no other schema is generated. This only happens if the _io.quarkus:quarkus-oidc_ extension is enabled.
|Add the following to your *application.properties* file:
`quarkus.smallrye-openapi.auto-add-bad-request-response=false`

* This property ensures that "400 Bad Request" outputs are not added to the auto-generated OpenAPI specifications.

|Workflow persistence
|When running Business Services using workflow functionality configured with a MS SQL Server instance, database deadlocks may occur.
|

|DMN Editor: does not support DMN 1.6 Simplified `InputData` Assignment Across Nested Imports
|Users who rely heavily on imported DMN models to build modular DMN models with layered imports, may encounter issues when their model depends on transitively imported Input Data nodes. This refers to Input Data defined in a model that is imported indirectly through another model. As a result, models using transitive Input Data cannot be:

* Evaluated using DMN Runner

* Tested using Scenario and Simulation files

|To avoid this issue, users must restructure their models to avoid relying on nested imports for Input Data.

|DMN Editor: Copy and paste of data type property creates non-unique copy
|When users attempt to speed up the creation of custom structures by copying and pasting structure properties, will encounter a limitation where the pasted property is not treated as a unique instance.

Although it is valid to have multiple structures with properties of the same name (for example, `Car.Price` and `House.Price`), the editor links the copied property to its original. As a result, any modification made to the pasted property (for example, `House.Price`) will also affect the original (`Car.Price`), and vice versa.

|To avoid this issue, users should manually create the new structure property instead of copying it. 

|DMN Editor: Does not autocomplete decision name when required decision uses namespace in `href`
|In DMN models, when a required decision is referenced by using a full namespace in the `href` attribute (e.g., <requiredDecision href="http://www.example.org/Definitions01.xml#prebureauriskDec01"/>), the expression editor fails to offer autocompletion for that decision. (eg. `prebureauriskDec01` is not in theautocompletion suggestions). This issue only affects references within the same DMN model. 

|To ensure autocompletion works as expected, do not use namespaces in `href` attributes when referencing decisions within the same DMN model. Use relative references (for example, `href="#decisionName"`) instead.

|DMN Editor: Copy of a Decision Service cause visually confusing diagram.
|When users copy and paste a group of nodes that are either connected to, or contained within a Decision Service, the pasted result may behave unexpectedly.
|To avoid this issue, do not copy Decision Service nodes together with other connected nodes in a single operation. Instead you should copy and paste the nodes outside the Decision Service, and separately back into the Decision Service, before copy and pasting the Decision Service nodes. This split approach helps preserve correct edge behavior and avoids visual inconsistencies in the diagram.

|DMN Runner: Interpreting `split("abc", 22)` results incorrectly in B-FEEL
|There are B-FEEL expressions, like `split("abc", 22)` that are invalid but comparing B-FEEL with FEEL, defines non-null result for them. Here it is an empty collection [] and DMN Runner does not display these results.
|There is no workaround for affected expressions. DMN Runner will show inappropriate values when using B-FEEL.

|DMN Runner: Time input is always marked as error
|In the DMN Runner panel, `time` input fields are consistently flagged as erroneous, even when the input is valid and no actual error occurs during evaluation. You may believe your input is incorrect or causing evaluation issues, when the logic executes correctly.
|Ignore the error indication unless it is confirmed to be affecting the evaluation results.
|===
