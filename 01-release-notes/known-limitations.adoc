Before you start using {PRODUCT_LONG}, review the known limitations. Workarounds are included with the limitations when possible.

Table 1. Known limitations

[%autowidth]

|Limitation |Description |Versions |Workaround

|BPMN Editor: Timer configuration resets when editing multiple Timer Events.
|When you configure two timer nodes in a BPMN file, the settings of the first timer node reset incorrectly after you navigate away and return to it. The editor resets the timer option to "Fire multiple times" and changes the syntax dropdown to ISO, even though the CRON value remains in the text field.
|{VERSION}
|After you configure the first timer node, click any other node before configuring the second timer node. This action prevents the reset and preserves the correct timer option and syntax selection.

|BPMN Editor: Compensation Associations rendering as Sequence Flows.
|When a BPMN diagram contains Compensation Associations — connections that link an activity to its compensation handler — the BPMN Editor incorrectly renders them as Sequence Flows. This visual misrepresentation can cause confusion when reading or editing diagrams that use compensation logic.
|{VERSION}
|No general workaround

|Native compilation support for workflow projects.
|Workflow (BPMN) projects do not support native compilation in {PRODUCT_SHORT} {VERSION_X} and earlier 9.x versions. Using certain dependencies (for example, Data-Index, Jobs-Service) might cause native builds to fail due to missing reflection metadata.
|{VERSION}
|Do not use native compilation if your _Business Services_ include stateful workflow.

|OpenAPI spec auto-generation when using the _io.quarkus:quarkus-oidc_ extension.
|The _io.quarkus:quarkus-smallrye-openapi_ extension will cause errors when starting a Business Service if the _io.quarkus:quarkus-oidc_ extension is also present and no other schema is generated. This only happens if the _io.quarkus:quarkus-oidc_ extension is enabled.
|{VERSION}
a|Add the following to your `application.properties` file:
`quarkus.smallrye-openapi.auto-add-bad-request-response=false`

* This property ensures that "400 Bad Request" outputs are not added to the auto-generated OpenAPI specifications.

|DMN Editor: No support for DMN 1.6 Simplified `InputData` Assignment Across Nested Imports
a|Users who rely heavily on imported DMN models to build modular DMN models with layered imports may encounter issues when their model depends on transitively imported Input Data nodes. This refers to Input Data defined in a model that is imported indirectly through another model. As a result, models using transitive Input Data cannot be:

* Evaluated using DMN Runner

* Tested using Scenario and Simulation files

|{VERSION}
|To avoid this issue, restructure your models to avoid relying on nested imports for Input Data.

|Developer Tools for VS Code: Extension update does not refresh the `bamoe.accelerators.definitions` setting.

|{VERSION}
a|Manually edit the `settings.json` file using one of the following methods:

* Delete the `bamoe.accelerators.definitions` setting (preferred).

|Kafka consumer group ACL configuration requires review.
|{PRODUCT_SHORT} includes Apache Kafka components affected by CVE-2026-41115. This issue is caused by a discrepancy between the Kafka documentation and the actual authorization behavior of the CONSUMER_GROUP_DESCRIBE API. The Kafka implementation correctly requires the DESCRIBE permission on a GROUP resource, while the documentation previously indicated that READ permission was required. No software fix is available because the implementation is functioning as intended. However, existing Kafka ACL configurations may require review to ensure permissions are granted appropriately.
|{VERSION}
|Review Kafka consumer group ACLs and verify that permissions are configured according to the corrected authorization model. Grant DESCRIBE permissions only where required and remove unnecessary permissions to maintain the principle of least privilege.

|Developer Tools for VS Code: Switching between BPMN Editor and BPMN Editor (classic) causes elements to disappear.
|Switching between the BPMN Editor and BPMN Editor (classic) for the same file can cause elements to disappear. For example, gateway conditional expressions and Business Rule Tasks with DMN implementation properties set may be lost after opening and saving the file in the other editor.
|{VERSION}
|To avoid this issue, do not switch between the BPMN Editor and BPMN Editor (classic) for the same file. Complete all edits in one editor.

|_Business Services_ compiled and built with JDK 17 deployed to canvas-dev-deployment-quarkus-blank-app may encounter issues. 
|As the Java 17 {PRODUCT_SHORT} variant of the Canvas Dev Deployment feature is no longer shipped you may encounter unexpected issues if you try to run a _Business Service_ compiled and built with JDK 17 using a Canvas Dev Deployment. JDK 21 is generally backwards compatible with JDK 17, but if a _Business Service_ contains a hard Maven Java dependency (for example a build profile scoped exclusively to JDK 17 or a compiler toolchain configuration that pins to JDK 17) it could fail to build or behave unexpectedly at runtime. This scenario goes beyond simple bytecode compatibility and may affect users whose projects rely on JDK-17-specific Maven behavior or activated profiles.
|{VERSION}
|Check your _Business Service_ projects for hard Maven Java version dependencies and consider upgrading to Java 21 if they cannot be removed.
