= Collecting and sending metrics to IBM Software Central
include::../partials/attributes.adoc[]
include::../styles/images.adoc[]

To maintain compliance with IBM licensing terms and conditions, you must collect license and usage metrics (VPC Count) for {PRODUCT} and upload manually or automatically to IBM Software Central (SWC). The tool you use will depend on your deployment environment:

 * IBM License Service (ILS) and IBM® Usage Metering Service (UMS) are used for deployments in a containerized environment. UMS captures business value metrics and generates usage reports, which can be used for auditing purposes and evidence of compliance.
 * IBM License Metric Tool (ILMT) is used for deployments in a non-containerized environment.

In addition if you install (see xref:https://www.ibm.com/docs/en/cloud-paks/foundational-services/4.x_cd?topic=usage-metering-service[IBM Usage Metering Service]) you can collect additional metrics (e.g., Node Instance Count) and generate usage reports which can be used for auditing or to track adoption of {PRODUCT_SHORT}, and that can be visualized in IBM Software Central.

If ILS is temporarily unavailable the last reported value continue to be used. Data synchronizes automatically when connectivity is restored, see xref:https://www.ibm.com/docs/en/cloud-paks/foundational-services/4.x_cd?topic=license-service[ILS Documentation] for more details.

For non-containerized deployments, failure handling is managed by ILMT as documented in xref:https://www.ibm.com/docs/en/license-metric-tool[ILMT Documentation].

== Working in a containerized environment
The `includeSWCUpload` annotation is included for all {PRODUCT_SHORT} components when you install the Dev and Runtime Environments or create Business Services with the Accelerators (see xref:managing-license-entitlements[Managing your license entitlements]). When combined with customer-configured entitlement keys, this annotation enables the upload of contractual metrics to IBM Software Central.

The following describes the process for setting up metric uploading in a containerized environment (Kubernetes or OpenShift):

. Generate an IBM Entitlement Key through the xref:https://myibm.ibm.com/products-services/containerlibrary[IBM Container Library]

. Install IBM License Service (or upgrade to) ILS version 4.x or higher, using instructions in the [ILS Documentation](https://www.ibm.com/docs/en/cloud-paks/foundational-services/4.x_cd?topic=license-service))

. Create an OpenShift secret with the entitlement key: 
* `oc create secret`

. Configure ILS with the entitlement key: 
*`oc apply`

. Install {PRODUCT_SHORT} components using Helm charts where the `includeSWCUpload: true` annotation is automatically included (see xref:development-environment.adoc#dev-env-helm[Installing Development environment] or runtime-environment.adoc#runtime-env-helm[Installing Runtime environment]). 

. For customer-created _Business Services_, define the required annotations in a version-controlled deployment YAML file that can be used by your GitOps or CI/CD process (see xref:managing-license-entitlements.adoc#business-service-container-deployment[Managing your license entitlements])

Steps 3 and 4 define the connection and authentication necessary to connect your cluster to IBM's licensing infrastructure.  If you choose not to configure an entitlement key, {PRODUCT_SHORT} product metrics cannot be automatically uploaded and you will need to do this manually. 

VPC count data is uploaded to Software Central once per day (configurable). A single payload is used to send multiple metrics that are correlated for each capability. Data from local storage can be obtained through REST API as a snapshot file or a JSON object. It can then be used for local dashboarding or sent to reporting tools, such as IBM License Service Reporter (LSR).

=== Configuring Adoption Metric upload
If you would like to obtain more visibility on the adoption of {PRODUCT_SHORT} and the deployment of _Business Services_ across your organization you must install IBM Usage Metering Service in your {PRODUCT_SHORT} namespace. The additional adoption metrics collected in {PRODUCT_SHORT} deployments in a containerized environments are:

* Process Step Executions (NODE_INSTANCE_COUNT): Total count of workflow node executions across all process instances
* Monthly Active Users (MAU): Tracked via UMS infrastructure

Follow this procedure to configure metric collection and visualization:

. Install IBM Usage Metering Service via the [IBM Cloud Pak Foundational Services installation with Helm Charts](https://www.ibm.com/docs/en/cloud-paks/foundational-services/4.x_cd?topic=services-installing-foundational-service-helm-charts). 

. Create BAMOE-Specific ServiceMeterDefinition:
** Create a `node-execution-meter.yaml` file. Choose the appropriate `productId` and `productName` based on your BAMOE product, here we have used PAMOE product details for example:
+
[source,yaml]
----
   apiVersion: operator.ibm.com/v1
   kind: IBMServiceMeterDefinition
   metadata:
     name: bamoe-node-execution-meter
     namespace: ${BAMOE_NAMESPACE}

   spec:
     mappingId: NODE_COUNT_MAPPING_0001
     processing: ADD
     repeat: true

     breakdownDefs:
       - breakdownBy:
           name: NODE_INSTANCE_COUNT
         groupBy:
           - deployments_type
           - version
           - license_type
         processing: ADD
         source: metricQuantity

     data:
       metricDescription: "Count of process nodes executed"
       metricName: NODE_INSTANCE_COUNT
       productId: "72984f114b54496a8a44be139154a988"
       productName: "IBM Process Automation Manager Open Edition"
----
   
. Apply the ServiceMeterDefinition:
   
[source,bash]
----
   oc apply -f node-execution-meter.yaml

   # Verify creation
   oc get ibmservicemeterdefinition -n ${BAMOE_NAMESPACE}
----

. Deploy your _Business Services_:
** BAMOE applications automatically include the UMS metrics collection add-on
** No code changes required in workflow applications
** Metrics collection starts automatically when workflows execute

. Verify BAMOE Metrics Collection**:

     After deploying and executing workflows:

     ```bash
     # Check BAMOE application logs for UMS connectivity
     oc logs -f deployment/<your-bamoe-app-name> -n ${BAMOE_NAMESPACE} | grep -i ums

     # Expected log message: "UMS API connectivity test successful"
     ```

     **View Collected BAMOE Metrics**:
     - Metrics automatically uploaded daily at 12:05 AM UTC to IBM Software Central
     - View metrics in IBM Software Central → Usage section


**BAMOE Application Configuration:**

Add the following properties to your BAMOE application's `application.properties` file to enable metrics collection:
```properties
# Enable UMS addon
bamoe.ums.enabled=true
# UMS environment type
bamoe.ums.environment=CONTAINERIZED
# UMS API endpoint - internal cluster service for upload port
bamoe.ums.api.endpoint=https://ibm-usage-metering-instance.<namespace>.svc.cluster.local:8081/api/v1/event
# UMS API authentication type
bamoe.ums.api.auth.type=bearer
# UMS API authentication token (reference to secret)
bamoe.ums.api.auth.token=${UMS_AUTH_TOKEN}
# UMS Logging (optional - for troubleshooting)
quarkus.log.category."com.ibm.bamoe.addons.ums".level=TRACE
quarkus.log.category."com.ibm.bamoe.addons.ums".min-level=TRACE
```
**Configuration Notes:**
- Replace `<namespace>` in the endpoint URL with your BAMOE namespace
- The `UMS_AUTH_TOKEN` should reference the token from the `ibm-usage-metering-upload-token` secret created by UMS
- Logging properties are optional and useful for troubleshooting metrics submission issues
**Disabling Metrics Collection:**
If you need to disable metrics collection, set the following property in your BAMOE application's `application.properties`:

```properties
# Disable UMS metrics collection
bamoe.ums.enabled=false
```

**Note:** Disabling metrics collection may impact license compliance visibility and reporting.


### What does this change mean for the new user/existing user?

**For New Users (First-time BAMOE Installation):**

- **Additional Setup Step**: Must install UMS service and create BAMOE ServiceMeterDefinition before deploying applications
- **BAMOE Add-on**: Metrics collection add-on automatically included in BAMOE 9.5.0+ applications
- **No Code Changes**: Workflow applications work without modification
- **Benefit**: Automatic workflow execution tracking and license compliance from day one






== Working with non-containerized Business Services 
When developing non-containerized _Business Services_ you can upload metrics by configuring IBM License Metric Tool(ILMT) version 9.2.43 (or higher) with an entitlement key. This key must be configured in the ILMT Console to enable upload to IBM Software Central of the contractual VPC metric collected via SWID tags and disconnected scanners. For more information on configuring your Business Service to use required SWID tags see xref:managing-license-entitlements.adoc[Managing your license entitlements]). 

. Install or upgrade to ILMT version 9.2.43 or higher (see [ILMT Documentation](https://www.ibm.com/docs/en/license-metric-tool))

. Ensure scanners are compatible with this version

. Generate an IBM Entitlement Key through the xref:https://myibm.ibm.com/products-services/containerlibrary[IBM Container Library]

. Configure the Software Central integration, see xref:https://www.ibm.com/docs/en/license-metric-tool/9.2.0?topic=central-configuring-connection-software[Configuring the connection to Software Central]
** This step includes configuring the IBM Entitlement Key in ILMT
** For air-gapped environments, configure the entitlement key in disconnected scanner configuration

. By default, after configuration, metrics are automatically uploaded once per day:
* For on-demand upload, see xref:https://www.ibm.com/docs/en/license-metric-tool/9.2.0?topic=central-uploading-contractual-data-software[Uploading contractual data to Software Central]

. Verify that SWID tags are properly installed and that metrics have been successfully uploaded to xref:https://swc.saas.ibm.com/en-us/software-central[Software Central]
