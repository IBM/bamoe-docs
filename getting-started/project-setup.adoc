= Setting up a _Business Services_ project
include::../partials/attributes.adoc[]
include::../styles/images.adoc[]

_Business Services_ are microservice Java applications built on top of Quarkus or Spring Boot, containing {PRODUCT_SHORT} runtime libraries and Business Automation assets such as Workflows (BPMN), Decisions (DMN), Rules (DRL), and spreadsheet Decision Tables (XLS or XLSX), following https://maven.apache.org/guides/introduction/introduction-to-the-standard-directory-layout.html[Maven's standard directory layout].

[#gs-accelerators]
== Introducing Accelerators
You can manually create everything from scratch, or use {PRODUCT_SHORT} to get started with pre-configured _Business Services_ project Accelerators.

In {PRODUCT_SHORT} you can use four Accelerators that correspond to the two cloud development frameworks supported by {PRODUCT_SHORT} - Quarkus and Spring Boot.

**`Quarkus (DMN)`**:: For _Business Services_ that contain Decisions, Rules, or spreadsheet Decision Tables.

**`Quarkus (Full)`**:: For _Business Services_ that contain stateful Workflows in addition to Decisions, Rules, or spreadsheet Decision Tables.

**`Spring Boot (DMN)`**:: For _Business Services_ that contain Decisions, Rules, or spreadsheet Decision Tables.

**`Spring Boot (Full)`**:: For _Business Services_ that contain stateful Workflows in addition to Decisions, Rules, or spreadsheet Decision Tables.

You can use Accelerators to set up your project in one of the following ways:

* Create new Decisions and/or Workflows on {CANVAS} then apply an Accelerator.
* Open a new or existing folder in VS Code with {DEV_TOOLS} installed, and apply an Accelerator.
* (Advanced) Create a Java project manually, adding dependencies to the _Business Service_ project configuration file, using Accelerators as reference.

[NOTE]
====
To ensure that newly created _Business Services_ in your organization follow the standards and best practices defined for your use cases, you can configure {CANVAS} and {DEV_TOOLS} with your custom Accelerators. For more information on configuring custom Accelerators on {CANVAS} and {DEV_TOOLS}, see xref:../installation/canvas.adoc[Installing → {CANVAS}] and xref:../installation/developer-tools-for-vscode.adoc[Installing → {DEV_TOOLS}].
====

== Starting on {CANVAS}

Before you create a new _Business Service_ project on {CANVAS}, make sure you have installed {CANVAS} on your device. 

To install {CANVAS}, follow instructions provided by your organization or install {CANVAS} locally. For more information on local installation, see xref:../installation/canvas.adoc[Installing → {CANVAS}].

To create a new _Business Service_ project on {CANVAS}, see xref:../tools/applying-accelerators.adoc[{CANVAS} → Using Accelerators].

=== Using {DEV_TOOLS} after starting on {CANVAS}

If you want to continue developing on {DEV_TOOLS} after starting on {CANVAS}, you can do one of the following options:

* Create a new Git repository in your Git provider of choice directly in {CANVAS}, then clone it locally.
* Download your newly created _Business Services_ project from {CANVAS} as a .zip file and unpack it in your computer.

[#starting-project-vscode]
== Starting on {DEV_TOOLS}

{DEV_TOOLS} provide commands to create a new _Business Service_ project using Accelerators.

To install {DEV_TOOLS} in the VS Code, see xref:../installation/developer-tools-for-vscode.adoc[Installing → {DEV_TOOLS}].

To use {DEV_TOOLS}, follow these steps:

. Open a new or existing folder in VS Code.
. _(optional)_ Create Business Automation assets, such as BPMN or DMN models.
. Run the `{DEV_TOOLS}: Apply Accelerator` command.
. Select the Accelerator you want to apply (DMN or Full, Quarkus or Spring Boot).

After completing the steps, your _Business Service_ project on {PRODUCT_SHORT} is ready in the currently open folder. Additionally, a new Git repository is initiated, if the currently open folder is not a Git repository. 

If you have any existing Business Automation assets or modifications, your assets are moved to the corresponding locations, and modifications in your staging environment are kept, so you remain in control of your development flow.

== (Advanced) Manually creating a Java project

If you have your own preferences when creating new projects, create your Java project manually. You can decide which {PRODUCT_SHORT} dependencies you need based on xref:../reference-guide/maven-repository-libraries.adoc[Reference → {MVN_REPO} libraries].

If you are planning on running Decisions, Rules, and/or spreadsheet Decision Tables on embedded Java mode using programmatic {PRODUCT_SHORT} Java API, see xref:../editing/dmn-decisions-embedded-java-mode.adoc[Executing Decisions in embedded Java mode] or xref:../editing/drl-rules-embedded-java-mode.adoc[Executing Rules in embedded Java mode].
