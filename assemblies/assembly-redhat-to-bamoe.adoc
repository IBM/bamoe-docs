= Upgrading from Red Hat to IBM Business Automation Manager Open Editions

This section describes how to upgrade from {RH_PAM} or {RH_DM} to {PRODUCT} {VERSION_80}. You will need to complete this upgrade before moving to the current {PRODUCT_SHORT} version 9.4.x.

If you have designed your jBPM application using KIE Server with Spring Boot and want to move from the latest community version to the enterprise-supported {PRODUCT_SHORT} 8.0.x, see https://community.ibm.com/community/user/automation/blogs/tim-wuthenow/2023/06/16/community-to-enterprise-bamoe[Moving from Community to Enterprise versions]. Both projects use Maven-based architectures, which simplifies the migration process.

If your current application is based on {RH_BPMS}, you must first upgrade to {RH_PAM}/{RH_DM} 7.x before moving to {PRODUCT}. For more information see https://docs.redhat.com/en/documentation/red_hat_process_automation_manager/7.0/html/migrating_from_red_hat_jboss_bpm_suite_6.4_to_red_hat_process_automation_manager_7.0/migration-overview-con.html[Migrating from Red Hat JBoss BPM Suite 6.4 to Red Hat Process Automation Manager 7.0].

If you are currently on RHPAM/RHDM 7.13.5, you can upgrade directly to any {PRODUCT_SHORT} 8.0.x release. For older versions of RHPAM/RHDM, you must first upgrade to RHPAM/RHDM 7.13.5 and then upgrade to any {PRODUCT_SHORT} 8.0.x release, see https://access.redhat.com/documentation/en-us/red_hat_process_automation_manager/7.13/html-single/installing_and_configuring_red_hat_process_automation_manager/index#assembly-patching-and-upgrading[Patching and upgrading Red Hat Process Automation Manager].

=== Procedure

The following steps are typically involved in upgrading from {RH_PAM} / {RH_DM} to {PRODUCT_LONG}:

.Prerequisites
Ensure the following tools are installed before starting the upgrade:

* https://openjdk.org[JDK 11]
* https://maven.apache.org[Apache Maven 3.8.6] or later

== Step 1: Download Product Archives

The first step in upgrade is to download the product archives from either {PRODUCT_FIX_CENTRAL_PAGE}[IBM Fix Central] _(which requires an active support subscription to {PRODUCT})_ or via the {DEV_PROGRAM_PAGE}[IBM Business Automation Manager Open Editions Developer Program] _(subject to its terms)_. 

You will need to download the new versions of the product components that you have installed in your development and production environments: {CENTRAL}, {KIE_SERVER}, the {HEADLESS_CONTROLLER}, the {DECISION_ENGINE} or standalone {CENTRAL} to be reinstalled.

To manage the migration of your data you will also need to download the `bamoe-version-add-ons.zip` file which contains a data migration tool as well as additional product components that may be required:

** **Migration tool**: Automates migration steps from Red Hat JBoss BPM Suite 6.4 to {PRODUCT_SHORT} 8.0, handling project structure, system configuration, forms, and POMs migration
** **Process engine (jBPM)**: Lightweight engine for executing business processes and cases, can be embedded in custom applications
** **Decision engine (Drools)**: Lightweight engine for business rules evaluation, complex event processing, and DMN execution
** **Smart Router**: Provides load balancing, request routing, and data aggregation across services
** **Headless Controller**: Control unit for managing connected Process Servers via REST API
** **Process instance migration tool**: Standalone web application for migrating business process models between versions
** **Dashbuilder runtime**: Standalone web application for visualizing monitoring data from KIE Server datasets
** **Sample Case Management application**: Example application demonstrating case widgets for domain-specific case applications

For all {PRODUCT_SHORT} Product Archives, see {PRODUCT_DOWNLOAD_LINK}[IBM Business Automation Manager Open Editions {ENTERPRISE_VERSION} downloads].

== Step 2: Update Maven Configuration and settings

{MAVEN_SITE_URL_BASE}[Apache Maven] is a software project management and comprehension tool. Based on the concept of a project object model (POM), Maven can manage a project's build, reporting and documentation from a central piece of information.
{PRODUCT_LONG} relies on Maven in order to build various types of deployable artifacts, such as decision service applications.
For a quick start, see {MAVEN_SITE_URL_GETTING_STARTED}[Maven Quick Start Guide].  

The `settings.xml` file is a repository for customizing Maven’s global operational parameters, distinguishing itself from the `pom.xml` by its non-association with particular projects.

This file includes configurations such as the location of the local repository, alternative sources for remote repositories, inputting credentials, among others.

There are two directories for the storage of the settings.xml file:

- Maven Installation Directory: Found at `${Maven.home}/conf/settings.xml`, this location reflects the settings applied universally across all Maven projects on the system.
- User-Specific Configuration: Located at `${user.home}/.m2/settings.xml'`, this directory allows for the storage of user-specific Maven settings.

Users can tailor their Maven environment to better suit their development needs by using these configurations.

[NOTE]
====
The first `settings.xml` is also referred to as `global settings`, and the second is referenced as user settings.
Both are combined with users taking precedence.
====

[TIP] 
====
If you need to create user-specific settings from scratch, copy the global settings from your Maven installation to your `_${user.home}/.m2_` directory.
Maven's default `_settings.xml_` is a template with comments and examples so you can quickly tweak it to match your needs.
_If you are looking to learn more about how to manage your various Maven settings, visit  https://maven.apache.org/settings.html[Maven Settings Reference]._
====

=== Update to use the Maven Bill of Materials (BOM)

A bill of materials (BOM) is a list of the parts or components that are required to build a product.
BOMs are ordinary `pom.xml` files — they contain no source code and their only purpose is to declare their bundled modules.

.Always use the Maven Bill-of-Materials (BOM)
[IMPORTANT]
====
It is highly recommended to use bill of materials (BOM) to manage project dependencies, as it simplifies dependency management by organizing a group of dependencies under a single version. 
====

A Bill of materials (BOM) can be added to an existing POM file by adding it to the **_dependencyManagement_** section as a dependency with a pom type:

include::../_artifacts/maven-bom-now.adoc[]

When a bill of materials (BOM) is used, it is not necessary to specify the dependency's version, as that appears from the BOM, so your dependencies end up like the following:

[source,xml]
----
<dependencies>
    <dependency>
        <groupId>org.drools</groupId>
        <artifactId>drools-compiler</artifactId>
    </dependency>
</dependencies>
----

[NOTE]
====
During the course of your Maven dependency update, if you encounter any dependencies that are *not* included in the bill of materials (BOM), then use the Maven Library Version noted in the table below, such as:
====

[source,xml]
----
<dependencies>
    <dependency>
        <groupId>org.drools</groupId>
        <artifactId>drools-compiler</artifactId>
        <version>VERSION</version>
    </dependency>
</dependencies>
----

== Step 3: Using migration tool to prepare Business Central .niogit directory for upgrade

The `.niogit` directory of your Business Central distribution contains all Business Central data. You can use the Business Central migration tool on your `.niogit` directory to prepare project data and system configurations for migration to {PRODUCT_SHORT}. 

.Prerequisites

* {PRODUCT_SHORT} 8.0.x is installed. 
+
NOTE: Do not run {PRODUCT_SHORT} 8.0.x Business Central until you have completed the steps in this section. 
+
* Red Hat Process Automation Manager 7.13.5 is installed and Business Central is not running on Red Hat Process Automation Manager 7.13.5. 
* JDK 8 is installed and is available on the path where the project migration tool will be installed.

*Procedure*

. Locate the `bin/.niogit` directory in your Red Hat Process Automation Manager 7.13.5 installation and locate the same directory in your new {PRODUCT_SHORT} 8.0.x installation. For example:
+
[source,shell]
----
~/$RHPAM_7.13.5_HOME/bin/.niogit
----
+
[source,shell]
----
~/EAP_HOME/bin/.niogit
----
+

. In your command terminal, copy the `.niogit` directory from your 7.13.5 Business Central installation to the bin folder of the new {PRODUCT_SHORT} 8.0.x installation directory:
+
[source,shell]
----
cp -r /$RHPAM_7.13.5_HOME/bin/.niogit  ~/EAP_HOME/bin/
----
+
The copied `.niogit` folder is the directory that the migration tool will prepare for {PRODUCT_SHORT} 8.0.x. The original `.niogit` folder remains in your Red Hat Process Automation Manager 7.13.5 installation and will not be modified by the migration tool in this procedure.
+

. In the {PRODUCT_SHORT} 8.0.x bin directory, delete the `.index` directory. You must delete this folder because {PRODUCT_SHORT} 8.0.x comes with certain updates that are not compatible with Red Hat Process Automation Manager 7.13.5. The bin directory will be re-indexed after the migration when you start {PRODUCT_SHORT} 8.0.x. 

. Note the path to the copied `.niogit` directory for {PRODUCT_SHORT} 8.0.x. The path will be required when you run the migration tool. 
//+
//If you encounter errors or notice any missing data in Decision/Business Central, you can restore the contents in the backup folder within the `bamoe-$VERSION-update` folder to revert the update tool changes.
//You can also reinstall the relevant release artifacts from your previous version of {PRODUCT}.
//After restoring your previous distribution, you can try again to run the update.
//+

. If you have specific `dependencies`, `repositories`, or `pluginRepositories` that you want to add, remove, or update as part of the project migration, create a `pom-migration.json` file containing these elements. When you run the migration tool, the tool will prompt you if you want to include this file in the migration.
+
The `pom-migration.json` file requires the following sections:
+
* `"dependencies":[]`
* `"repositories-add":[]`
* `"repositories-remove":[]`
* `"repositories-update-urls":[]`
* `"pluginRepositories-add":[]`
* `"pluginRepositories-remove":[]`
* `"pluginRepositories-update-urls":[]`

If any of these elements do not apply to your project, include them as empty sections to prevent parsing errors.

. In the {PRODUCT_SHORT} 8.0.x installation directory, extract the `bamoe-8.0.x-migration-tool.zip`. The migration tool is in the bin directory. 

. In your command terminal, navigate to the temporary directory where you extracted the `bamoe-8.0.x-migration-tool` folder and run the migration tool. `$RHPAM_NIOGIT_DIR` is the path to the `.niogit` directory that you previously copied to the {PRODUCT_SHORT} 8.0.x installation. 

+

On Linux or UNIX-based systems: 
+

[source,shell]
----
cd $INSTALL_DIR/BAMOE_8.0-migration-tool/bin
./migration-tool.sh -t $BAMOE_NIOGIT_DIR
----
+
On Windows systems: 
+
[source,shell]
----
cd $INSTALL_DIR\BAMOE_8.0-migration-tool\bin

----

In the command prompt that appears, the following options are displayed: 
+
* Project structure migration
* System configuration directory structure migration
* Forms migration
* POMs migration
* All
* Exit
+
. Select the *All* option to run migrations in sequence. Enter `yes` each time you are prompted to run a specific migration option. Migration options are described in following table and can also be run individually in any order:
+
[cols="1,1"]
|===
|Migration options |Description

|Project structure migration 
|Migrates the Red Hat Process Automation Manager 7.13.5 project repository structure to the new project-oriented structure used in Red Hat Process Automation Manager 7.13.5.

|System configuration directory structure migration 
|Migrates the `system.git` repository structure used in Red Hat Process Automation Manager 7.13.5 to the new structure used in {PRODUCT_SHORT} 8.0.x.

|Forms migration
|Migrates forms created in the Red Hat JBoss BPM Suite forms designer to the new forms designer.

|POMs migration
|Updates `pom.xml` files with dependencies required for {PRODUCT_SHORT} 8.0.x. If you want to include a path to an external `pom-migration.json` file that you created previously, enter `yes` when prompted and enter the path.
|===
+
. After the tool finishes running, enter the option to Exit the migration tool.
. Navigate to the `.niogit` directory to inspect the restructured contents through the 8.0.x Business Central UI. 
The `.niogit` directory structure is now compatible with Business Central in {PRODUCT_SHORT} 8.0.x. Project directories are in separate repositories and all other related configurations have been migrated. 

== Step 4: Update Persistence

For applications based on {RH_PAM}, you may be required to update the runtime database.
For upgrading the database, the easiest way is to do it in sequence, as most of the jobs are very small (re: 2-4 lines of SQL).
They are all mapped by the version progression, so it will be fairly quick.
So, for instance, if you are running a PostgreSQL database, you must do the following:

. Connect to your database instance using your method of preference.
. Apply the SQL scripts appropriate for the version you are upgrading from up to RHPAM 7.13.x.

[source,shell,subs="attributes+"]
----
...
$ psql -h $dbhost -U $user < rhpam-7.11-to-7.12.sql
$ psql -h $dbhost -U $user < rhpam-7.12-to-7.13.sql
$ psql -h $dbhost -U $user < rhpam-7.13-to-7.13.1.sql
...
----

[NOTE]
====
{PRODUCT_SHORT} version {VERSION_80}'s database is compatible with {RH_PAM} 7.13.x, so all you need to do is to update the database to that level, and you will be set to migrate the rest of your application.
====

Once you have executed these SQL statements, your datasource is now up to date.
If you are running a different database than PostgreSQL, replace the `psql` command with your appropriate database and tooling of choice; the files should largely be the same.
